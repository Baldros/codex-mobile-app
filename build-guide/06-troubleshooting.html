Troubleshooting

Quando algo falha, costuma ser operação — não código. Comece pelo sintoma na tabela, confirme a causa provável e aplique a correção. Em seguida, rode o checklist de 5G.

Conexão & túnel SSH

SintomaCausa provávelAção
Timeout no SSHEndpoint fechado, CGNAT ou endereço erradoValidar o endereço público/IPv6, o NAT, o roteador ou a VPN.
SSH autentica mas o health falhaBridge parado ou porta remota erradaTestar o /health no desktop e conferir a porta de loopback do bridge.
PermitOpen nega a conexãoPorta remota diferente da liberadaConferir que o forward aponta para o loopback do bridge declarado no sshd_config.
Funciona no Wi-Fi, não no 5GNAT / roteador / firewallTestar o endpoint externo de outra rede; considerar VPN/overlay.
Health oscilaComputador suspendendo ou rede instávelAjustar energia (sem suspensão) e o backoff de reconexão.
SSH continua pedindo senhaPermissões do authorized_keys incorretasVer sshd.log por “bad ownership or modes” e refazer as permissões do capítulo 3.

O log do servidor SSH no Windows costuma estar em:

caminho do log
C:\ProgramData\ssh\logs\sshd.log

Falha de gradlew clean em CMake/autolinking

Sintoma típico:

erro
add_subdirectory given source ... /codegen/jni/ which is not an existing directory

Isso não é erro de SSH — é estado nativo incremental antigo. Faça o reset nativo e repita o clean:

PowerShell · Terminal 2comum
cd <PROJECT_ROOT>\mobile\android

$targets = @("app\.cxx", "app\build\generated\autolinking")
foreach ($t in $targets) {
  if (Test-Path -LiteralPath $t) { Remove-Item -LiteralPath $t -Recurse -Force }
}

.\gradlew.bat clean --no-daemon --console=plain --stacktrace

Aparece um IP de Wi-Fi como “Bridge”

Em build de dev isso é normal (Metro), mas não deve ocorrer no APK release. Corrija nesta ordem:

  1. Confirme que EXPO_PUBLIC_BRIDGE_URL não está definido no terminal do build.
  2. Confirme que CODEX_MOBILE_API_BASE_URL e CODEX_MOBILE_SSH_TUNNEL_LOCAL_URL apontam para o loopback do celular.
  3. Limpe os dados antes de instalar: adb shell pm clear <APP_PACKAGE_ID>.
  4. Rebuilde com o fluxo release.

Quando pedir ajuda

Ao reportar um problema, inclua (sem segredos): o modo de gateway, o status do túnel (connecting/ready/erro), se o /health responde no desktop, e o trecho relevante do sshd.log. Isso resolve a maioria dos casos sem expor nenhuma credencial.
