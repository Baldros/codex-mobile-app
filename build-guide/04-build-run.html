Capítulo 4

Build & Run

Agora juntamos tudo: o bridge no ar, as variáveis de build no ambiente, o APK release com o bundle JS embutido e a instalação por USB. Salvo onde indicado, tudo aqui roda em terminal comum.

Use dois terminais: o Terminal 1 fica com o bridge rodando; o Terminal 2 faz a configuração e o build. Substitua <PROJECT_ROOT> pela pasta onde você clonou o repositório.

1 · Subir o Codex Bridge Terminal 1

No backend, instale as dependências, compile e deixe rodando. O runtime app-server entrega a experiência rica com histórico e aprovações.

PowerShell · Terminal 1comum
cd <PROJECT_ROOT>\backend
npm install
$env:CODEX_BRIDGE_RUNTIME = "app-server"
npm run build
npm run start

Em um terceiro terminal (ou antes de iniciar o build), valide a saúde pelo loopback. Lembre que <BRIDGE_PORT> é a porta que você escolheu e que existe só em 127.0.0.1:

PowerShellcomum
Invoke-RestMethod "http://127.0.0.1:<BRIDGE_PORT>/health"

Esperado: status = ok, codex_ready = true e active_transport = app-server. Deixe o bridge rodando.

2 · Configurar as variáveis de build Terminal 2

O Expo lê estas variáveis no momento do build (via app.config.js) e as injeta no app. A chave privada é lida de arquivo, nunca escrita à mão — e essas variáveis jamais devem ser commitadas.

PowerShell · Terminal 2comum
cd <PROJECT_ROOT>\mobile

# Garante que nenhuma URL de dev sobrescreva a config do tunel
Remove-Item Env:\EXPO_PUBLIC_BRIDGE_URL -ErrorAction SilentlyContinue

$KeyPath = "$env:USERPROFILE\.ssh\codex_mobile_rsa"

# --- Transporte ---
$env:CODEX_MOBILE_GATEWAY               = "ssh_tunnel"
$env:CODEX_MOBILE_API_BASE_URL          = "http://127.0.0.1:<LOCAL_FORWARD_PORT>"
$env:CODEX_MOBILE_SSH_TUNNEL_LOCAL_URL  = "http://127.0.0.1:<LOCAL_FORWARD_PORT>"

# --- Endpoints SSH em cascata (LAN, IPv6, VPN...) ---
$env:CODEX_MOBILE_SSH_REMOTE_HOSTS      = "<SSH_ENDPOINT_1>,<SSH_ENDPOINT_2>"
$env:CODEX_MOBILE_SSH_USERNAME          = "<SSH_USER>"

# --- Credencial (lida do arquivo, nunca hardcoded) ---
$env:CODEX_MOBILE_SSH_AUTH_MODE         = "private_key"
$env:CODEX_MOBILE_SSH_PRIVATE_KEY_PEM   = Get-Content $KeyPath -Raw

# --- API remota: o loopback do bridge, do outro lado do tunel ---
$env:CODEX_MOBILE_SSH_REMOTE_API_HOST   = "127.0.0.1"
$env:CODEX_MOBILE_SSH_REMOTE_API_PORT   = "<BRIDGE_PORT>"

# --- Confirmacao explicita de credencial embutida ---
$env:CODEX_MOBILE_ALLOW_EMBEDDED_SSH_SECRET = "true"
VariávelPapel
CODEX_MOBILE_GATEWAYModo de transporte: ssh_tunnel para produção interna.
CODEX_MOBILE_API_BASE_URLURL que o app chama — sempre o loopback do próprio celular.
CODEX_MOBILE_SSH_REMOTE_HOSTSLista de endpoints SSH tentados em cascata.
CODEX_MOBILE_SSH_USERNAMEO usuário dedicado do capítulo 3.
CODEX_MOBILE_SSH_PRIVATE_KEY_PEMConteúdo da chave privada, lido do arquivo em tempo de build.
CODEX_MOBILE_SSH_REMOTE_API_*Loopback do bridge, alcançado pelo túnel.
CODEX_MOBILE_ALLOW_EMBEDDED_SSH_SECRETConfirmação consciente de que o build embute um segredo.
Qualquer segredo no APK é recuperável

A chave embutida pode ser extraída por quem tiver o binário. Isso só é aceitável no perfil interno porque o usuário SSH é dedicado, sem privilégios, e o PermitOpen limita o forward ao bridge. Leia a página de segurança antes de distribuir qualquer build.

3 · Instalar deps e gerar o projeto nativo Terminal 2

PowerShell · Terminal 2comum
cd <PROJECT_ROOT>\mobile
npm install

# Gera a pasta android/ nativa (apenas se ainda nao existir)
if (-not (Test-Path .\android\gradlew.bat)) {
  npx expo prebuild --platform android
}

O APK release usa HTTP simples sobre o loopback dentro do túnel. Confirme que o <application> em mobile\android\app\src\main\AndroidManifest.xml contém android:usesCleartextTraffic="true". É seguro porque o tráfego só ocorre em 127.0.0.1.

4 · Conferir o aparelho Terminal 2

Com o celular conectado e a depuração autorizada, ele deve aparecer como device:

PowerShellcomum
adb devices

5 · Gerar o APK release Terminal 2

Este é o build “de verdade”: APK release com o bundle JS embutido, sem depender do Metro.

Antes do clean: reset de estado nativo (recomendado)

O clean do React Native pode falhar quando sobra estado incremental de codegen/autolinking. Removê-lo antes evita o erro de CMake. Os caminhos abaixo são relativos ao projeto:

PowerShell · Terminal 2comum
cd <PROJECT_ROOT>\mobile\android

$targets = @("app\.cxx", "app\build\generated\autolinking")
foreach ($t in $targets) {
  if (Test-Path -LiteralPath $t) { Remove-Item -LiteralPath $t -Recurse -Force }
}

Compile. Para iterar rápido, gere só arm64-v8a (a maioria dos aparelhos atuais). Para um APK distribuível multi-arquitetura, omita o parâmetro -PreactNativeArchitectures.

PowerShell · Terminal 2comum
cd <PROJECT_ROOT>\mobile\android

.\gradlew.bat clean --no-daemon --console=plain --stacktrace

.\gradlew.bat :app:createBundleReleaseJsAndAssets :app:assembleRelease `
  -PreactNativeArchitectures=arm64-v8a `
  --no-daemon --console=plain --stacktrace

O APK fica em:

saída
<PROJECT_ROOT>\mobile\android\app\build\outputs\apk\release\app-release.apk

6 · Instalar e abrir Terminal 2

PowerShell · Terminal 2comum
adb install -r .\app\build\outputs\apk\release\app-release.apk

# Abre o app pelo launcher
adb shell monkey -p <APP_PACKAGE_ID> -c android.intent.category.LAUNCHER 1

Se a instalação falhar por assinatura incompatível, remova o app antigo e reinstale. Para um estado totalmente limpo, limpe os dados antes:

PowerShellcomum
adb uninstall <APP_PACKAGE_ID>
# ou, para apenas zerar dados:
adb shell pm clear <APP_PACKAGE_ID>

adb install -r .\app\build\outputs\apk\release\app-release.apk

<APP_PACKAGE_ID> é o identificador de pacote configurado no app (veja mobile\app.config.js / o manifest).

7 · Verificar no app

Abra a tela de Settings e confira o diagnóstico de transporte:

  • Gateway: ssh_tunnel
  • URL local: o loopback do celular
  • API remota: o loopback do bridge
  • SSH user: seu usuário dedicado
  • Config: ok

Toque em refresh ou dispare uma ação que chame o bridge. O túnel deve sair de connecting para ready. Depois, valide também fora do Wi-Fi, em 5G — o capítulo 6 traz o checklist.

Se o campo Bridge mostrar um IP de Wi-Fi em vez do loopback, é configuração antiga de dev. Confirme que EXPO_PUBLIC_BRIDGE_URL não está definido, que as URLs locais apontam para o loopback, limpe os dados (pm clear) e rebuilde.

Fluxo de desenvolvimento (opcional)

Para iterar UI/código rapidamente existe o fluxo dev, que depende do Metro e pode mostrar um IP de LAN. Use só para desenvolvimento — não para entregar:

PowerShellcomum
cd <PROJECT_ROOT>\mobile
adb reverse tcp:8081 tcp:8081
npx expo run:android

Para um APK que o usuário só abre e usa, fique com o fluxo release das seções 5 e 6.
