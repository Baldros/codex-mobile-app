Chapter 4

Build & Run

Now we put everything together: the bridge in the air, the build variables in the environment, the APK release with the built-in JS bundle and USB installation. Except where indicated, everything here runs in common terminal.

Use two terminals: the Terminal 1 keeps the bridge running; the Terminal 2 does the configuration and build. Replace <PROJECT_ROOT> by the folder where you cloned the repository.

1 · Climb the Codex Bridge Terminal 1

In the backend, install the dependencies, compile and run. The runtime app-server delivers rich experience with history and approvals.

PowerShell Terminal 1common
cd <PROJECT_ROOT>\backend
npm install
$env:CODEX_BRIDGE_RUNTIME = "app-server"
npm run build
npm run start

In a third terminal (or before starting the build), validate health through loopback. Remember that <BRIDGE_PORT> is the door that you chose and that exists only in 127.0.0.1:

PowerShellcommon
Invoke-RestMethod "http://127.0.0.1:<BRIDGE_PORT>/health"

Expected: status = ok, codex_ready = true and active_transport = app-server. Leave the bridge running.

2 · Configure build variables Terminal 2

Expo reads these variables at build time (via app.config.js) and injects them into the app. The private key is file read, never written by hand — and these variables never must be committed.

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile

# Ensure that no dev URL overwrites the tunnel config
Remove-Item Env:\EXPO_PUBLIC_BRIDGE_URL -ErrorAction SilentlyContinue

$KeyPath = "$env:USERPROFILE\.ssh\codex_mobile_rsa"

# --- Transport ---
$env:CODEX_MOBILE_GATEWAY = "ssh_tunnel"
$env:CODEX_MOBILE_API_BASE_URL = "http://127.0.0.1:<LOCAL_FORWARD_PORT>"
$env:CODEX_MOBILE_SSH_TUNNEL_LOCAL_URL = "http://127.0.0.1:<LOCAL_FORWARD_PORT>"

# --- Cascading SSH endpoints (LAN, IPv6, VPN...) ---
$env:CODEX_MOBILE_SSH_REMOTE_HOSTS = "<SSH_ENDPOINT_1>,<SSH_ENDPOINT_2>"
$env:CODEX_MOBILE_SSH_USERNAME = "<SSH_USER>"

# --- Credential (read from file, never hardcoded) ---
$env:CODEX_MOBILE_SSH_AUTH_MODE = "private_key"
$env:CODEX_MOBILE_SSH_PRIVATE_KEY_PEM = Get-Content $KeyPath -Raw

# --- Remote API: the bridge loopback, on the other side of the tunnel ---
$env:CODEX_MOBILE_SSH_REMOTE_API_HOST = "127.0.0.1"
$env:CODEX_MOBILE_SSH_REMOTE_API_PORT = "<BRIDGE_PORT>"

# --- Explicit confirmation of embedded credentials ---
$env:CODEX_MOBILE_ALLOW_EMBEDDED_SSH_SECRET = "true"
VariablePaper
CODEX_MOBILE_GATEWAYMode of transport: ssh_tunnel for in-house production.
CODEX_MOBILE_API_BASE_URLURL that the app calls — always the loopback from the cell phone itself.
CODEX_MOBILE_SSH_REMOTE_HOSTSList of SSH endpoints attempted to cascade.
CODEX_MOBILE_SSH_USERNAMEThe dedicated user of chapter 3.
CODEX_MOBILE_SSH_PRIVATE_KEY_PEMContents of the private key, read from the file at build time.
CODEX_MOBILE_SSH_REMOTE_API_*Bridge loopback, reached through the tunnel.
CODEX_MOBILE_ALLOW_EMBEDDED_SSH_SECRETConscious confirmation that the build embeds a secret.
Any secret in the APK is recoverable

The embedded key can be extracted by anyone who has the binary. This is only acceptable in the internal profile because the SSH user is a dedicated, unprivileged user and the PermitOpen limits the forward to the bridge. Read the security page before distributing any build.

3 · Install deps and generate the native project Terminal 2

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile
npm install

# Generate the native android/ folder (only if it does not already exist)
if (-not (Test-Path .\android\gradlew.bat)) {
  npx expo prebuild --platform android
}

The APK release uses plain HTTP over loopback inside the tunnel. Confirm that the in mobile\android\app\src\main\AndroidManifest.xml contains android:usesCleartextTraffic="true". It is safe because traffic only occurs in 127.0.0.1.

4 · Check the device Terminal 2

With the cell phone connected and debugging authorized, it should appear as device:

PowerShellcommon
adb devices

5 · Generate the APK release Terminal 2

This is the “real” build: APK release with the JS bundle embedded, without depending on Metro.

Before clean: native state reset (recommended)

O clean React Native may fail when incremental state remains codegen/autolinking. Removing it first avoids the CMake error. The paths below are relating to the project:

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile\android

$targets = @("app\.cxx", "app\build\generated\autolinking")
foreach ($t in $targets) {
  if (Test-Path -LiteralPath $t) { Remove-Item -LiteralPath $t -Recurse -Force }
}

Compile. To iterate quickly, only generate arm64-v8a (most current devices). For a multi-architecture distributable APK, omit the parameter -PreactNativeArchitectures.

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile\android

.\gradlew.bat clean --no-daemon --console=plain --stacktrace

.\gradlew.bat :app:createBundleReleaseJsAndAssets :app:assembleRelease `
  -PreactNativeArchitectures=arm64-v8a `
  --no-daemon --console=plain --stacktrace

The APK is at:

exit
<PROJECT_ROOT>\mobile\android\app\build\outputs\apk\release\app-release.apk

6 · Install and open Terminal 2

PowerShell Terminal 2common
adb install -r .\app\build\outputs\apk\release\app-release.apk

# Open the app through the launcher
adb shell monkey -p <APP_PACKAGE_ID> -c android.intent.category.LAUNCHER 1

If the installation fails due to an incompatible signature, remove the old app and reinstall. For a completely clean state, clear the data before:

PowerShellcommon
adb uninstall <APP_PACKAGE_ID>
# or, to just reset data:
adb shell pm clear <APP_PACKAGE_ID>

adb install -r .\app\build\outputs\apk\release\app-release.apk

<APP_PACKAGE_ID> is the bundle identifier configured in the app (see mobile\app.config.js /o manifest).

7 · Check in the app

Open the screen Settings and check the transport diagnosis:

  • Gateway: ssh_tunnel
  • Local URL: cell phone loopback
  • Remote API: the bridge loopback
  • SSH user: your dedicated user
  • Config: OK

Tap refresh or trigger an action that calls the bridge. The tunnel must leave connecting to ready. Then also validate off Wi-Fi, in 5G — the chapter 6 bring the checklist.

If the Bridge field shows a Wi-Fi IP instead of the loopback, it is an old dev configuration. Confirm that EXPO_PUBLIC_BRIDGE_URL is not defined, that local URLs point to the loopback, clear the data (pm clear) and rebuild.

Development flow (optional)

To iterate UI/code quickly there is the dev flow, which depends on Metro and can show a LAN IP. Use only for development — not for delivery:

PowerShellcommon
cd <PROJECT_ROOT>\mobile
adb reverse tcp:8081 tcp:8081
npx expo run:android

For an APK that the user only opens and uses, stick with the release flow from sections 5 and 6.
