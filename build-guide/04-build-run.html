Chapter 4

Build & Run

Now we put everything together: the bridge in the air, the build variables in the environment, the APK release with the built-in JS bundle and USB installation. Except where indicated, everything here runs in common terminal.

Use two terminals: the Terminal 1 keeps the bridge running; the Terminal 2 does the configuration and build. Replace <PROJECT_ROOT> by the folder where you cloned the repository.

1 · Climb the Codex Bridge Terminal 1

In the backend, install the dependencies, compile and run. The runtime app-server delivers rich experience with history and approvals.

PowerShell Terminal 1common
cd <PROJECT_ROOT>\backend
npm install
npm run build

$env:NODE_ENV = "production"
$env:CODEX_BRIDGE_RUNTIME = "app-server"
$env:CODEX_BRIDGE_HOST = "<HOST_TUNNEL_ADDRESS>"
$env:CODEX_BRIDGE_PORT = "<BRIDGE_PORT>"
node dist/server.js

In a third terminal (or before starting the build), validate health over the tunnel address:

PowerShellcommon
Invoke-RestMethod "http://<HOST_TUNNEL_ADDRESS>:<BRIDGE_PORT>/health"

Expected: status = ok, codex_ready = true and active_transport = app-server. Leave the bridge running.

Then confirm where it is actually listening — this is the check that matters:

PowerShellcommon
Get-NetTCPConnection -State Listen -LocalPort <BRIDGE_PORT> | Select-Object LocalAddress
Only the tunnel address may appear

If that command shows 0.0.0.0, the API is exposed to your whole LAN — and this API has no authentication. Stop and fix CODEX_BRIDGE_HOST before continuing. There is currently no guard in the code that refuses a public bind for you.

2 · Configure build variables Terminal 2

Expo reads these variables at build time (via app.config.js) and injects them into the app. With WireGuard as the transport there are only two, and neither is a secret.

Prefer a .env.local file in mobile/, which is Git-ignored:

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile

@'
CODEX_MOBILE_GATEWAY=http
CODEX_MOBILE_API_BASE_URL=http://<HOST_TUNNEL_ADDRESS>:<BRIDGE_PORT>
'@ | Set-Content -Path .env.local -Encoding ascii

Get-Content .env.local

Or, equivalently, as environment variables in the same terminal that runs the build:

PowerShell Terminal 2common
# Ensure no dev URL overrides the build config
Remove-Item Env:\EXPO_PUBLIC_BRIDGE_URL -ErrorAction SilentlyContinue

$env:CODEX_MOBILE_GATEWAY = "http"
$env:CODEX_MOBILE_API_BASE_URL = "http://<HOST_TUNNEL_ADDRESS>:<BRIDGE_PORT>"
VariableRole
CODEX_MOBILE_GATEWAYTransport mode. http — the app talks straight to the bridge over the tunnel.
CODEX_MOBILE_API_BASE_URLThe bridge's address inside the private network.
No secret enters the APK

Every CODEX_MOBILE_SSH_* variable from the old design is gone, including CODEX_MOBILE_ALLOW_EMBEDDED_SSH_SECRET. There is no key, user or password to embed — the device's WireGuard key is generated by the WireGuard app and stays on the phone. That removes an entire class of problem rather than mitigating it.

Legacy defaults still exist in the repo

mobile/app.config.js, mobile/eas.json and the fallback in parseGatewayMode still default to ssh_tunnel. The first one matters: if the variable does not reach the build process — file not loaded, wrong terminal, variable cleared — the config falls back to ssh_tunnel silently, and the APK ships with the old gateway and no error anywhere.

That is why the Gateway: http check in step 7 is not a formality. It is the only place the mistake becomes visible.

3 · Install deps and generate the native project Terminal 2

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile
npm install

# Generate the native android/ folder (only if it does not already exist)
if (-not (Test-Path .\android\gradlew.bat)) {
  npx expo prebuild --platform android
}

The APK release uses plain HTTP inside the tunnel. Confirm that the <application> in mobile\android\app\src\main\AndroidManifest.xml contains android:usesCleartextTraffic="true". It is acceptable because WireGuard already provides confidentiality and authenticity — but note the flag is app-wide, so a Bridge URL saved outside the tunnel would also travel in the clear. See the security page.

4 · Check the device Terminal 2

With the cell phone connected and debugging authorized, it should appear as device:

PowerShellcommon
adb devices

5 · Generate the APK release Terminal 2

This is the “real” build: APK release with the JS bundle embedded, without depending on Metro.

Before clean: native state reset (recommended)

O clean React Native may fail when incremental state remains codegen/autolinking. Removing it first avoids the CMake error. The paths below are relating to the project:

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile\android

$targets = @("app\.cxx", "app\build\generated\autolinking")
foreach ($t in $targets) {
  if (Test-Path -LiteralPath $t) { Remove-Item -LiteralPath $t -Recurse -Force }
}

Compile. To iterate quickly, only generate arm64-v8a (most current devices). For a multi-architecture distributable APK, omit the parameter -PreactNativeArchitectures.

PowerShell Terminal 2common
cd <PROJECT_ROOT>\mobile\android

.\gradlew.bat clean --no-daemon --console=plain --stacktrace

.\gradlew.bat :app:createBundleReleaseJsAndAssets :app:assembleRelease `
  -PreactNativeArchitectures=arm64-v8a `
  --no-daemon --console=plain --stacktrace

The APK is at:

exit
<PROJECT_ROOT>\mobile\android\app\build\outputs\apk\release\app-release.apk

6 · Install and open Terminal 2

PowerShell Terminal 2common
adb install -r .\app\build\outputs\apk\release\app-release.apk

# Open the app through the launcher
adb shell monkey -p <APP_PACKAGE_ID> -c android.intent.category.LAUNCHER 1

If the installation fails due to an incompatible signature, remove the old app and reinstall. For a completely clean state, clear the data before:

PowerShellcommon
adb uninstall <APP_PACKAGE_ID>
# or, to just reset data:
adb shell pm clear <APP_PACKAGE_ID>

adb install -r .\app\build\outputs\apk\release\app-release.apk

<APP_PACKAGE_ID> is the bundle identifier configured in the app (see mobile\app.config.js /o manifest).

7 · Check in the app

Make sure the WireGuard tunnel is active on the phone, then open Settings:

  • Bridge: the host's tunnel address and bridge port
  • Gateway: http
  • Config: OK

Go back to the home screen; the status should turn online. Pick an allowed repository and start a conversation to exercise a real Codex run. Then validate again off Wi-Fi, on mobile data — chapter 6 has the checklist.

The "Tunnel build" diagnostics block (Local URL, SSH user, Active endpoint) is empty with gateway = http. That is expected — there is no embedded tunnel to report on.

If the Bridge field shows an old address

adb install -r preserves the app's stored preferences, and the saved URL wins over the build-time default. Fix it in Settings → Bridge → Save URL rather than clearing app data, which also wipes everything else.

Useful side effect: an APK built with the old ssh_tunnel gateway works over the VPN with no rebuild. Saving a URL different from the embedded tunnel URL disables the embedded tunnel and the app falls back to plain HTTP.

Development flow (optional)

To iterate UI/code quickly there is the dev flow, which depends on Metro and can show a LAN IP. Use only for development — not for delivery:

PowerShellcommon
cd <PROJECT_ROOT>\mobile
adb reverse tcp:8081 tcp:8081
npx expo run:android

For an APK that the user only opens and uses, stick with the release flow from sections 5 and 6.
