Capítulo 3

Túnel SSH

O SSH é a única porta de entrada que cruza a rede. Por isso ele recebe um usuário dedicado, uma chave por dispositivo e um sshd trancado para só encaminhar até o bridge. Faça este capítulo com calma — é o que protege a sua máquina.

Por que um usuário dedicado

Nunca use sua conta principal do Windows para o túnel. Um usuário separado dá:

  • Menor raio de impacto — sem privilégios administrativos, a credencial vale pouco se vazar.
  • Revogação simples — basta remover uma linha do authorized_keys daquele dispositivo.
  • Hardening focado — você restringe esse usuário no sshd sem afetar o resto do sistema.

1 · Criar o usuário dedicado Administrador

Crie uma conta local exclusiva do túnel (aqui chamada de <SSH_USER>, ex.: codex_ssh). Não a adicione ao grupo de Administradores.

PowerShellAdministrador
# Pede a senha de forma interativa, sem deixá-la no histórico
$Password = Read-Host "Senha forte para o usuario SSH" -AsSecureString
New-LocalUser -Name "<SSH_USER>" -Password $Password `
  -Description "Usuario dedicado para o tunel SSH do Codex Mobile"

Para o perfil de chave já ficar pronto, faça um login local com esse usuário uma vez (ou deixe que o passo do authorized_keys crie a pasta). Assim a pasta C:\Users\<SSH_USER> passa a existir.

2 · Gerar a chave SSH Terminal comum

Gere a chave no seu usuário de desenvolvimento. Cada dispositivo deve ter a sua própria chave, para poder ser revogado isoladamente.

Formato da chave importa no Android

Para o cliente SSH embutido no APK, use uma chave RSA 4096 em formato PEM. Chaves ED25519 funcionam no ssh.exe do Windows, mas podem falhar no cliente Android com desconexão na pré-autenticação. Para testes interativos no desktop, ED25519 é ótima.

PowerShellcomum
ssh-keygen -t rsa -b 4096 -m PEM `
  -f "$env:USERPROFILE\.ssh\codex_mobile_rsa" `
  -C "codex-mobile-<dispositivo>"
PowerShellcomum
ssh-keygen -t ed25519 `
  -f "$env:USERPROFILE\.ssh\codex_mobile_ed25519" `
  -C "codex-mobile-<dispositivo>"
Sobre a passphrase

Deixar a passphrase em branco só se justifica porque a chave será embutida em um build automatizado. Em troca, trate o .ssh\ como segredo: nunca o versione, nunca o copie para fora e revogue a chave se o aparelho sair do seu controle.

3 · Instalar a chave pública no usuário SSH Administrador

O OpenSSH do Windows é rigoroso com permissões: se o authorized_keys ficar “aberto demais”, o login por chave falha em silêncio e cai para senha. Faça exatamente nesta ordem.

Etapa A — escrever a chave

PowerShellAdministrador
$sshUser = "<SSH_USER>"
$sshDir  = "C:\Users\$sshUser\.ssh"
$authKeys = "$sshDir\authorized_keys"

# Garante a pasta .ssh do usuario dedicado
New-Item -ItemType Directory -Path $sshDir -Force | Out-Null

# Le a sua chave PUBLICA (.pub) e adiciona ao authorized_keys
$pub = Get-Content "C:\Users\<SEU_USUARIO>\.ssh\codex_mobile_rsa.pub" -Raw
Add-Content -Path $authKeys -Value $pub -Encoding ascii

Etapa B — corrigir as permissões (crítico)

Só o dono (<SSH_USER>) e o SISTEMA podem acessar o arquivo:

PowerShellAdministrador
$authKeys = "C:\Users\<SSH_USER>\.ssh\authorized_keys"

# 1. Assume a posse para conseguir alterar as permissoes
takeown /f $authKeys /a

# 2. Concede acesso ao usuario dono e ao SISTEMA
icacls $authKeys /grant "<SSH_USER>:F"
icacls $authKeys /grant "SISTEMA:F"

# 3. Define o usuario dono como proprietario real
icacls $authKeys /setowner "<SSH_USER>"

# 4. Remove a heranca (limpa acessos de outros usuarios)
icacls $authKeys /inheritance:r

# 5. Remove o acesso do grupo de Administradores (o SSH exige isso)
icacls $authKeys /remove "Administradores"
Windows em inglês?

Troque Administradores por Administrators e SISTEMA por SYSTEM. Liste os nomes corretos do seu sistema com net localgroup.

4 · Validar o login local Terminal comum

Teste a chave pelo loopback. Deve entrar sem pedir senha:

PowerShellcomum
ssh -i "$env:USERPROFILE\.ssh\codex_mobile_rsa" <SSH_USER>@127.0.0.1

Se ainda pedir senha, o problema costuma estar nas permissões do authorized_keys. Veja o log do servidor e procure por “bad ownership or modes”:

caminho do log
C:\ProgramData\ssh\logs\sshd.log

5 · Hardening do sshd Administrador

Edite C:\ProgramData\ssh\sshd_config e adicione um bloco que tranca o usuário do túnel. O ponto mais importante é o PermitOpen: ele garante que essa credencial só consegue encaminhar para o bridge, e para mais nada.

sshd_config
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
AllowUsers <SSH_USER>
AllowTcpForwarding local
PermitOpen 127.0.0.1:<BRIDGE_PORT>
X11Forwarding no
AllowAgentForwarding no
MaxAuthTries 2
LoginGraceTime 20

Aplique reiniciando o serviço:

PowerShellAdministrador
Restart-Service sshd
DiretivaO que faz
PasswordAuthentication noElimina brute force online; só chave entra.
AllowUsers <SSH_USER>Só o usuário dedicado pode logar via SSH.
AllowTcpForwarding localPermite apenas local forward (o que o túnel usa).
PermitOpen 127.0.0.1:<BRIDGE_PORT>Restringe o forward ao loopback do bridge — nada mais é alcançável.
MaxAuthTries 2 / LoginGraceTime 20Reduz a janela de tentativas e conexões ociosas.

Se, por necessidade de build interno, você optar por PasswordAuthentication yes, isso só é aceitável com usuário dedicado, senha forte e única por dev, firewall controlado e PermitOpen mantido. Prefira chave sempre que possível.

6 · Acesso remoto para 5G

Para usar o app fora de casa, o celular precisa de uma rota até o sshd — e somente até o SSH. O bridge continua no loopback. Há três caminhos, do mais seguro ao mais trabalhoso:

VPN / overlay recomendado

Uma rede privada (ex.: WireGuard/Tailscale) coloca o celular e o desktop na mesma rede lógica. Você discа o SSH por um IP da overlay e não abre nada no roteador.

IPv6 direto

Se ambos têm IPv6 público, o celular alcança o desktop pelo endereço IPv6 dele, sem NAT de porta. Mantenha o firewall liberando só o SSH.

Encaminhamento de porta

O roteador encaminha uma porta pública escolhida por você até a porta do SSH no desktop. Funciona, mas expõe o SSH à internet — exige senha/chave forte e monitoramento.

No app, você cadastra os endpoints como uma lista em cascata (LAN, IPv6, VPN) e o cliente tenta cada um até conectar — detalhe no capítulo de build.

Independente do caminho, nada de HTTP é publicado. Mesmo no 5G, o app fala com o loopback local e o bridge segue inacessível diretamente pela internet.

7 · Revogar um dispositivo

Se um aparelho ou build sair do seu controle, remova a linha correspondente do authorized_keys — é por isso que cada dispositivo tem a sua própria chave. A revogação acontece no servidor e tem efeito imediato nas próximas conexões.

PowerShellAdministrador
# Abra o arquivo e apague a linha da chave daquele dispositivo
notepad "C:\Users\<SSH_USER>\.ssh\authorized_keys"
