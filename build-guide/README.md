# Codex Mobile - Build Guide

Interactive HTML documentation for building and installing **Codex Mobile**, an Android client that operates a local Codex CLI session on your desktop over a **private WireGuard VPN**, including on mobile data.

The guide is organized as a **step-by-step path**: each page covers one build phase, with progress checklists, copyable code blocks, light/dark theme switching, and sidebar navigation. The goal is to keep the end-to-end process organized so you do not get lost between terminals, variables, and the device.

> **GitHub does not render HTML.** If you click the files below in the repository, you will see the raw source code, which is not convenient to follow.
> To view the guide as intended, styled and interactive, **download/clone the repository and open `build-guide/index.html` in your browser**. Double-clicking the file is enough; no server is required.

## The Build in 1 Minute

A quick summary of the full path, so you know what you are getting into before downloading.

### The Idea

The mobile app is only an **operations client**. Everything sensitive, including the Codex CLI, OpenAI login, workspace, and permissions, stays on the **desktop**, which is the trust boundary. The phone joins a private WireGuard network and talks to a local **Codex Bridge** inside it. **The only thing reachable from outside is the VPN's UDP port.** The bridge is never published to the internet.

**No secret is embedded in the APK.** The phone's private key is generated by the WireGuard app and never leaves the device; revoking a device is deleting a `[Peer]` block on the host, with no rebuild.

### You Will Need (on the Windows Desktop)

- **Node.js** 20 LTS+ · **JDK 17** · **Android SDK** (command-line tools) · **WireGuard for Windows**
- An **Android device** with USB debugging enabled and the free **WireGuard** app installed

### The Path, Step by Step

1. **Bridge running** - start Codex Bridge bound to the tunnel address, and confirm `/health`.
2. **WireGuard tunnel** - generate a host key, let the phone generate its own, exchange **public** keys, and give each device its own `/32`.
3. **Build variables** - two of them, `CODEX_MOBILE_GATEWAY=http` and the bridge URL. Neither is a secret.
4. **Native project** - `npm install` + `expo prebuild`.
5. **Release APK** - `gradlew assembleRelease` with the JS bundle embedded (no Metro).
6. **Install and open** - `adb install` and launch the app.
7. **Validate** - confirm the handshake and the app going `online`, on Wi-Fi and then off Wi-Fi.

### Regular Terminal x Administrator

The **build itself does not require Administrator**. Node, npm, Expo, Gradle, and `adb` run in a regular terminal. What requires **Admin** is the one-time system setup: installing WireGuard, setting its tunnel service to start automatically, inspecting it with `wg show`, and machine-level variables.

You do **not** need to create a Windows Firewall rule — WireGuard installs its own filters in the Windows Filtering Platform, which never appear in Defender Firewall.

### Security Highlights

- The VPN removes the class of problem that an embedded credential creates. It does **not** add authentication to the bridge — **the bridge has none**, so anything that reaches its address has full control. Read chapter 5 before deciding this is acceptable for your situation.
- The bridge must bind only to its tunnel address. **Never** forward the bridge port on a router; the only port that may reach you is WireGuard's UDP port.
- **Never** commit `.env`, keys, or configuration files containing them. Your public IPv6 address, dynamic DNS name, and peer public keys are identifiers, not design — keep them out of anything public too.
